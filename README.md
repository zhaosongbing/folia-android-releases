# Folia for Android — 在线更新源

这个仓库只用来放 **APK 与更新日志**，应用内的「在线更新」就是从这里读版本号。

- 安装包：见右侧 [Releases](../../releases)
- 上游仓库：[Timingyyds/folia-android](https://github.com/Timingyyds/folia-android)
- 代码仓库：[zhaosongbing/folia-android](https://github.com/zhaosongbing/folia-android)
- 应用内的检查地址：`https://api.github.com/repos/zhaosongbing/folia-android-releases/releases/latest`

每次发布都会上传一个 `.apk` 资产；应用发现新版本会弹窗显示版本对比和更新日志，
点「下载安装包」用系统浏览器打开 APK 直链，由系统安装器接管安装。

> 这是个人移植的非官方 Android 版本，与原项目无关。

## 更新日志

### 0.7.21.29（测试）

# Folia 0.7.21.29 更新日志

这一版把上一条反馈里的五件事逐条落实：双指缩放与进入播放页的闪烁、智能过渡下定时关闭不退出、播放时屏幕仍然会熄、播放页控件改成按住才出现且整体放大。另外内测通道取消了，测试通道改成需要口令。

## 双指缩放不再闪

上一版加了双指缩放，但缩放过程里整面墙会一抖一抖地闪。原因不是渲染慢，是两处机制撞在一起：

**一、每帧都在重建格子。** 缩放时相机每动一点就触发一次可见性重算（cull），重算会把落在范围内的格子重新挂一遍。现在改成只有边缘真的进出视野时才重算，松手后再补一次收尾重算。

**二、像素吸附把锚点推来推去。** 墙的世界层一直把位移吸附到整设备像素，这是为了不让浏览器重新栅格化。但缩放时这个吸附会让锚点在 1 像素内反复跳，加上缩放倍率本身没有做吸附，画面就在「对齐 / 不对齐」之间来回切。现在缩放过程中暂停位移吸附、倍率吸附到 1/2000，松手后用 160 毫秒的过渡把状态收干净。

同时，缩放期间「缝」（主页与歌单页的内容栏）的 18px 高斯模糊也会被临时撤掉 —— 模糊每帧都要按新尺寸重新采一次背后的画面，是这套界面里最贵的一笔。

## 进入播放页不再闪一下

播放页打开时有两段动画叠在一起：一段 350 毫秒的淡入，和一段 300 毫秒的背景滤镜退出。两段的时长与曲线都不同，中间会露出一帧「滤镜已经变了但透明度还没跟上」的状态。现在播放页直接给最终滤镜、不走过渡，淡入缩到 240 毫秒且只动透明度。

## 定时关闭：到时真的退出

打开智能过渡（Automix）时定时关闭不生效，这条是真 bug。智能过渡下有两路音频在交叉淡出，上一版的定时关闭只让「当前这一路」暂停，另一路还在放，听感上就是没关。现在到点先挂起两路，再走退出流程。

而且 Android 上原本根本没有退出通道 —— 那条路只给桌面版写过。这一版补上了原生退出：先 `finishAndRemoveTask` 收掉任务，再结束进程。**定时关闭是关掉 APP，不是暂停播放**，文案也照这个改了。

## 保持屏幕常亮

三个原因叠在一起：

1. 只写了窗口标志，没有写 View 级的 `keepScreenOn`，部分机型只认后者。
2. 后台回来时有个短路判断，导致恢复前台后标志没有被重设。
3. 判断用的是对外展示的播放状态，比真实状态晚一拍，播放刚开始那一下没置标志。

这一版三条都改了：标志双写、`onResume` 重设、读真实播放状态，并且同时要系统唤醒锁与浏览器唤醒锁，还补了窗口重新获得焦点的复查。

## 播放页控件：按住才出现，整体放大

- 播放页的工具按钮与滑轨改成**长按约 0.4 秒出现，松手立即消失**，按住期间不会自己收回去（以前是点一下出现、3 秒后自己消失）。
- 播放页里按钮与滑轨整体放大一号：上一首/下一首从 40 加大到 48，播放键从 48 加大到 56，图标与时间字号一起上调，轨道变粗。首页与 Lattice 的底部胶囊保持原尺寸，不和墙的密度打架。
- 鼠标操作保持原样，不影响桌面端。

## 通道调整：内测通道取消，测试通道需要口令

- 更新通道现在只有两条：**正式** 与 **测试**。原来的内测通道已取消，历史的内测版本在解析上归到测试通道，旧版本仍能正常读到更新。
- 切到测试通道需要输入口令。口令只做 SHA-256 比对，代码里不存明文，也不会写进本地配置。

### 0.7.21.28（测试）

# Folia 0.7.21.28 更新日志

这一版修好了定时关闭，给主页与歌单页加了双指缩放，折叠组的毛玻璃可以单独调，另外动了拖动时偶尔闪一下的问题。

## 定时关闭：两个真原因

上一版加了定时关闭，但很多人点了开关没反应。查下来是两个问题，都不是「到点算错」（那段逻辑单测验证过是对的）：

**一、没设时长时，开关什么都不做。** 以前点了开关只弹一句「先设个时长」就结束了，而面板上的开关就在时长那一行上面一行，很容易让人以为开关坏了。现在打开时会自动补一个 15 分钟，并提示「没设时长，先按 15 分钟开始」。

**二、手机在后台会冻住计时器。** 定时关闭最典型的用法就是锁屏听着睡着，而 Android 的 WebView 在后台会把 `setInterval` 冻住甚至清掉，到点那一下整个被跳过。现在到点只有一个出口，由三条路进来：每秒一次的心跳、页面重新可见、窗口重新获得焦点。回前台会立刻核一次，不用再等下一秒。

## 主页与歌单页：双指缩放

在墙面上用两根手指捏合就能放大缩小，触控板上是双指捏合或按住 Ctrl 滚轮。缩放锚在两指中点：那一点下面的内容不动，看起来是「从这里放大」，而不是整面墙跳一下。

- 倍率夹在默认档位的 0.7 到 2.4 倍之间。
- 开关在**设置 → 主页与歌单 → 主页 → 双指缩放**，默认打开。关掉之后墙只平移，第二根手指不再触发缩放。
- 缩放倍率不保存，重开应用回到默认档位。

说明：缩放做在 Bravais 墙面（主页与歌单页共用这一面墙）。如果资料库界面选的是「Grid 网格」，那是另一套 3D 卡片流，没有这一项。

## 折叠组的毛玻璃可以单独调

**设置 → 通用 → 启动与窗口**里新增两项：折叠组卡片的模糊半径与不透明度，与上面的面板模糊/透明度分开存。

理由是卡片浮在面板之上，是第二层玻璃：面板调得很透时，卡片需要更实一点才看得清行文字；反过来面板很实、背后没有东西可透时，卡片的模糊只是白花钱。默认值与改动前一致（18px / 72%），不动就是原来的样子。

## 拖动时偶尔闪一下、抖一下

墙的世界层一直把位移吸附到整设备像素 —— 代码里写着理由：图层没有 `will-change` 时，位移的小数部分一变，浏览器就把整层丢掉重新栅格化。但「缝」（主页与歌单页真正的内容栏）的位移是手写的小数，绕过了这套吸附，拖动时它每帧重新栅格化，文字发虚、偶尔闪一下。

这一版把缝的位移与宽度也吸附到整设备像素，并且在缝变形的那几帧临时撤掉它自身的 18px 高斯模糊（模糊每帧都要按新尺寸重新采一次背后的画面，是这个界面里最贵的一笔），停下 140 毫秒后恢复。另外跳过了一部分没有变化的样式写入。

这条属于「照机制下手」：我们没有在你那台设备上复现到「偶尔」的时序。如果还有，请说清楚它发生在什么时候（拖动中 / 停手后 / 打开歌单时 / 切页签时），再往下查。

### 0.7.21.27（测试）

# Folia 0.7.21.27 更新日志

这一版把「屏幕常亮」修好了，补上带两种关闭方式的定时关闭，并加入「全部音源」搜索、播放失败自动换源、队列融合与平台徽章。

## 屏幕常亮：这次是真的常亮了

上一版的常亮只走了浏览器的 Screen Wake Lock，而这条 API 要 Chrome 84 才有 —— 车机与老平板的 WebView 大多停在 70 上下，开关看着是开的，屏幕照旧灭。同时那个锁被系统释放之后引用没清掉，回前台再也申请不回来。

现在改成一主一备两条通道：主通道是 Android 窗口标志 `FLAG_KEEP_SCREEN_ON`（新增的原生方法 `setKeepScreenOn`，回前台时在 `onWindowFocusChanged` 里重新贴一次），备通道才是浏览器的 Wake Lock；锁被系统收走时把引用清空，下次点亮可以重新申请。只有「正在播放」时才会持有，暂停即释放。

开关现在有两个入口，读写同一个字段，在哪边改都一致：

- 面板 → 控制页 → 屏幕常亮
- 设置 → 播放 → 行为

## 定时关闭：两种关闭方式

面板控制页与服务端设置页都加了这一组：

- 快捷时长 15 / 30 / 60 / 90 分钟，右侧可以按 5 分钟为单位自定义（上限 999 分钟）。
- **关闭方式**两种：**播完整首歌后关闭**与**直接关闭**（默认保持原来的行为，到点即停）。选前者时，到点不会拦腰截断正在放的这首，而是先挂起、等这首放完再停；那段时间面板上的倒计时会显示「已到点，等这首放完就停」。暂停状态或已经没有音频在放时，到点照旧立即执行。
- 关掉定时会连「等这首放完」的挂起状态一起清掉，不会在下一次放完时莫名停下来。

## 搜索：全部音源

搜索页的来源多了一项「全部音源」：一次搜遍所有已登录且支持搜索的平台，不必先切账号。各平台并发请求、按名次交错合并再按歌名去重，所以不会出现前排被单一平台占满；某个平台失败不影响整体结果，只有一个都问不到时才报错。命令面板里的「搜索当前来源」在选了「全部音源」时也保持这个范围，不会缩回单个平台。

## 播放失败：自动到别的音源找同一首

歌曲下架、没有音频、音频放不了、只有试听、要会员、要购买、要权限、地区限制这几种，以前只能报一句「放不了」。现在会先在本平台找同一首的其它版本（原有逻辑），找不到就去别的已配置平台搜同一首：

- 匹配刻意保守：歌名去掉括号补充与标点后必须完全相同，再要求歌手重合，或时长相差不超过 5 秒。换错一首比跳过一首更让人困惑。
- 命中之后直接把队列里这一条换成那边的歌、接着放，提示条写明是从哪个平台找到的。
- **一首歌只换一次**：如果换过去那边也放不了，就按正常失败处理，不会在两个平台之间来回弹。
- 连不上、未登录、未配置这几种不换 —— 换个平台不会让它们变好。

播放中途失败（媒体解码、音频不可播放）走同一套匹配，只是会从那首的开头重新放。

## 队列融合与平台徽章

- 切换在线平台不再清空播放队列：队列与正在放的那首原地保留，只重置搜索与集合导航。退出登录仍然会清空队列，那是另一回事。
- 打开在线歌单点「播放全部」时，新歌单**并入**当前队列（已在队列里的不重复添加），并提示「已并入当前队列（N 首）」，不再把排好的歌换掉。
- 队列拼贴墙与搜索结果行都按歌曲来源显示平台徽章，混着几个平台的队列一眼能看出哪首来自哪家。

## 网易云歌词：被风控时重试与降级

歌词接口返回 `code 2001`（操作频繁）、`-460`（请求异常）、`-447`（登录被风控）或 HTTP 429 时，以前是直接把空歌词交给界面。现在这几种按可重试处理：等 700ms 再要一次，还不行再等 2000ms 要一次，仍然被拦就降级到老接口 `/lyric?id=` 再试 —— 它要求的字段少，常常还能给。云盘歌曲的歌词拿不到时也会回落到普通歌词路径，而不是直接判成没有歌词。三种路径都拿不到，才按「没有歌词」显示。

### 0.7.21.26（测试）


### 车机与旧版 WebView 兼容

- **新增老内核构建产物**：这一版同时输出现代包和 legacy 包。legacy 包改用 `nomodule` + SystemJS 加载，并内置 core-js polyfill，覆盖到 Chrome 60 / Android 6 一档的 WebView，用来解决车机上「startup timed out. tap to reload」起不来的问题。
- **依赖全部本地打包**：删掉 `index.html` 里指向 CDN 的 importmap，React、framer-motion、lucide-react、i18next 等由构建直接打进安装包。启动不再需要访问外网，网络受限的设备也能进。
- **现代包补 polyfill**：给新内核也补上低版本 WebView 缺的 API，避免「能加载模块但运行时报错」。

### 说明

- 现代设备仍然走原来的现代包，启动路径不变。
- 由于同时打包两份产物，APK 体积会比上一版更大。
- 极老的内核（Chrome 67 以下）里，用到 BigInt 的个别模块仍可能报错；如果车机仍然起不来，需要进一步确认 WebView 版本。

# Folia 0.7.21.25 更新日志

这一版加了三通道更新，并整理了几个设置与墙上的小问题。

## 更新通道：正式版 / 内测版 / 测试版

设置 → 通用 → 在线更新里多了一项「更新通道」。三条通道发在同一个发布页，靠版本标号区分：

| 通道 | 版本标号 | 收到什么 |
| --- | --- | --- |
| 正式版 | `v0.7.22.0` | 只收正式发布 |
| 内测版 | `beta-v0.7.22.0` | 内测包 + 正式发布 |
| 测试版 | `dev-v0.7.22.0` | 测试包 + 内测包 + 正式发布 |

- 一个包就够：通道是应用内的设置，不用换安装包，覆盖安装照旧。换通道后下一次检查立即生效。
- 向下兼容：内测版用户在正式版发热修时也能收到，不会因为「正式版发了新版」而卡在旧的内测包上。
- 内测 / 测试的发布在发布页上标为「预发布」，不会被当成正式最新版；应用内按标号前缀自己挑，两边互不干扰。
- 换通道会清掉之前「稍后提醒」的记录 —— 那是另一条通道上的版本。

发布时指定通道：`scripts/publish-android-release.sh <apk> <notes> <version> beta`（省略通道就是正式版）。

## 定位按钮偶尔变成方形

根因是 Lattice 的一条样式：墙上的内容要贴成直角，所以有一条
`.lattice-queue-root *:not(.lattice-tools *):not(.lattice-back):not(.lattice-chrome button) { border-radius: 0 !important }`。
豁免名单里只有工具按钮、返回按钮那一圈，而定位按钮在 0.7.21.22 已经从工具按钮的竖列里搬出来、有了自己的锚点，
于是掉出了豁免范围，被这条规则压成直角。这条样式只在 Lattice 的样式加载之后才生效，所以表现是「偶尔」变方、
并且连它里面的定位光环一起变成方框。现在把定位按钮整棵子树加进豁免名单。

## 设置

- 「浮层位置与大小」里那两个单独占一行的「全部复位」不再单独成行：位置复位的按钮并进「编辑浮层位置」那一行，
  大小复位的按钮并进「四颗按钮大小」那一行。

### 0.7.21.24

# Folia 0.7.21.24 更新日志

编辑态与设置窗口这一轮，主要是把「浮层位置」从一堆滑杆改成拖拽，并把设置里的选项做成毛玻璃。

## 浮层位置：编辑态里拖，整组一起走

- **主页信息条的下部分整体可拖**：账户入口、工具坞、那颗「展开」尾巴原本只有工具坞跟着动，
  另两颗留在原处；现在三颗合成一组，一个虚线框，拖动整组同步，位置也一起记。
- **Bravais 墙面（集合页 / 海报页）的信息条同样可拖**：完整信息条的两排动作
  （播放全部 / 加入队列 / 收藏，以及列表 / ⋯ 更多）、海报页的底部都归到「下部分」，
  不再各动各的；「上部分」在首页窄缝是标题与页签，在集合页 / 面板 / 搜索页是返回与面包屑。
- **顶部提示改在编辑态里调**：编辑态会画一个提示占位（提示本身是短暂的，平时不在屏幕上），
  拖它就是在调提示的位置；设置里那两个上下 / 左右的滑杆随之移除。

## 长按滑轨不再断触

播放页右下角工具按钮的滑轨（按住往轨道方向划）之前会「拖到一半没了」。三处改动：

- 手势监听从按钮本身搬到 `window`，按 pointerId 只跟按下那一根手指；按钮在手势中被父级
  重渲染、被移位，或者指针被墙面的滚动抢走时，拖动也不会断。
- 长按不再触发文字选择与浏览器右键菜单（Android WebView 上这正是手势被收走的原因）。

# Folia 0.7.21.21 更新日志

## 播放破音

- **主链路新增软限幅（保险）**：整条链最后、进扬声器之前加了一级软限幅。此前每一级都可能把信号推过满刻度 —— 网易云只给 ReplayGain 的 gain、不给 peak，正向增益没有削波保护；均衡器多段同时提升；效果链的 punch 补偿增益；交叉淡化时两轨相加 —— 而系统的输出端只会硬削波，听到的就是「破音」。现在 0.95 满刻度以下严格直通（实测 0.5 倍信号进出都是 0.5000），以上用平滑曲线压住：实测 2 倍、4 倍、8 倍过载信号走完整条图，没有任何一个样本越过满刻度。
- **没有峰值信息时不再放大**：ReplayGain 的峰值是判断「放大了会不会削波」的唯一依据。缺失时（网易云只给 gain）以前会照搬正向增益，现在只衰减、不放大 —— 宁可轻一点，也不破音。

## 播放卡顿

- **音频缓冲加大**：音频上下文从默认的低延迟档改为 `playback` 档。默认档为压低延迟只用很短的输出缓冲，手机上主线程一抖（可视化一帧算得久、React 一次大重渲染、GC 一次回收）缓冲就见底，听到的就是断断续续。播放器不需要「手势到出声」的低延迟，用一点延迟换不断音。
- **终止每帧分配内存**：可视化音频桥每秒 60 次循环里原本每帧新建一块 1KB 的频谱数组，现在复用同一块。减少的垃圾会让 GC 少被唤醒，那种「偶尔一顿」的停顿来源之一就此消失。
- **续播护栏只操作当前 deck**：原生侧每秒的焦点续播护栏原来取 DOM 里第一个 `<audio>`，第一次交叉淡化之后活动 deck 变成 B，第一个是已经停下来的 A —— 护栏会去 `play()` 那条本该安静的热备 deck，白解码一首旧歌还让它的位置一路漂。现在按 `data-folia-active-deck` 只续播真正在发声的那一路。

## 验证方式

- 单元测试新增两条：限幅曲线（直线区透明、峰值到不了满刻度、单调）与 ReplayGain 增益选择（无峰值不放大、有峰值按剩余余量放）。
- 用 OfflineAudioContext 实测：单级限幅与整条链（音量→淡入→限幅→分析→输出）都不产生越界样本。
- 应用冒烟：两个 deck 正确，活动 deck 标记正确，无运行时错误。

## 一、双击反馈图标

前两次的修改分别用了「audio 元素的 paused」和「store 的 hook 值」，都不对。这次先说明错在哪：

- **读 audio 元素会反**：automix 为了无缝切歌会预热另一个 deck，那个 deck 的 `paused` 是 `false`（音量为 0，但确实在播）。「有任一 deck 在播就算在播」这个判据，会在你暂停的那一刻把状态读成「还在播放」。
- **读 store 的 hook 值也会反**：`showGestureCue` 是个 `useCallback`，读 hook 值等于读「上一次渲染时的状态」。播放/暂停刚切换完的那一帧，它手里还是旧值。

现在的做法是 `usePlaybackStore.getState().playerState === PlayerState.PLAYING`：同步读、没有闭包过期问题，也不受预热 deck 干扰。`playerState` 由 audio 的 `play` / `pause` 事件直接维护，是应用层唯一的播放语义。

语义仍是「即将变成什么」：播放时双击显示暂停图标，暂停时双击显示播放图标。

## 二、返回键改为先回主页

上一版修好了「返回键完全没反应」，但动作是直接退到桌面。现在按层级：

1. 退出确认框开着 → 关它
2. 更新弹窗 / 设置弹窗 / 命令面板 / 播放列表面板 → 逐个关
3. 其它自绘弹窗 → 派发 Escape
4. **播放页 → 回主页**
5. **bravais 墙的非根层（集合页、表单、面板）→ 退回上一层**
6. 都没有 → 按设置决定是否二次确认后才退桌面

第 5 条是直接触发缝里那颗 `‹` 返回按钮：bravais 没有把「返回」暴露成命令，那是唯一的入口，而程序触发 `click()` 不受 `visibility` 影响，缝收起时同样有效。

## 三、信息条下部分可调位置

新增「信息条下部分 · 左右 / 上下」两条滑块，与原来的「上部分」各自独立。主页作用于工具格（`.bravais-seam-dock`），bravais 集合页作用于底部那一排动作（`.bravais-seam-actions`）——两处用同一组值，切页面不会丢。

## 四、四颗浮层按钮的大小可调

设置路径：主页与歌单 → Bravais 墙面 →「浮层大小」。

| 可调项 | 基准 |
| --- | --- |
| 左上角返回按钮 | 40px |
| 右下角定位按钮 | 40px |
| 右下角工具按钮 | 48px |
| 思索按钮（触屏灯泡） | 48px |

用百分比（80%–180%）而不是绝对值，因为四颗的基准不同，绝对值会让四组滑块的刻度含义不一致。组内第一行有「全部复位」。

工具按钮那颗的缩放是整套的：滑轨长度、填充宽度、图标都按同一个比例走，不会出现「圆变大了但滑轨还是老长度」。思索按钮的热区也跟着按钮的新位置和尺寸重新计算——否则位置一改，按钮就挪出了自己的热区，收起后再也点不回来。

左上角返回按钮的位置改成了 CSS 变量（`--wall-back-x/y/scale`）而不是内联 `left/top`，这样窄屏的媒体查询基准不会被内联值覆盖。播放页那颗返回按钮现在读同一组值，三处天然一致。

## 一、双击播放/暂停的反馈图标

之前双击中区，反馈图标和实际动作相反。根因不在图标映射，而在状态来源：`onPause` 里有一条「程序化暂停」的分支会直接 return，不写 `setPlayerState(PAUSED)`。只要有一次暂停落到那条分支，store 就一直停在 PLAYING，下一次双击读到的就是「还在播放」，图标自然反过来。

现在改为直接读两个主音频 deck 的物理暂停态（`audio[data-folia-main-audio="1"]`）：暂停时两个 deck 都 `paused`，播放时至少有一个不是。这个信号不会滞后，也不受 store 遗留值影响。

## 二、去掉控制栏里的定位按钮

上一版把这颗准星塞进了展开态的按钮组。它不属于控制栏，已移除；定位仍由墙上原有的那颗按钮负责，且那颗现在可以单独调位置（见下文）。

## 三、四处浮层位置可自定义

| 可调项 | 作用 |
| --- | --- |
| 左上角返回按钮 · 左右 / 上下 | 海报墙与 Lattice 共用的那颗返回 |
| 右下角定位按钮 · 左右 / 上下 | 定位当前播放歌曲的准星 |
| 右下角工具按钮 · 左右 / 上下 | 打开工具面板的那颗 |
| 信息条上部分 · 左右 / 上下 | 主页信息条的标题、账户入口与页签整块 |

范围 ±120px，步长 1，**默认 0 = 与之前完全一致**。组内第一行有「全部复位」，8 个滑块调乱了一键回到默认。

实现上刻意避开 `transform`：返回按钮的悬停缩放与隐藏动画、定位按钮的滑入位移都写在 transform 上，用 transform 做偏移会把它们盖掉。所以返回与定位改用 `left/top`，工具按钮用负 margin（它同时还要叠加底栏抬升那个 MotionValue，覆盖掉就等于把底栏避让一起废了），只有信息条上部分用 `translate`（那一块没有别的 transform）。

## 四、返回键拦截修复

上一版完全没生效，根因是 `targetSdk` 已经是 36：Android 13（API 33）起系统走预测式返回，**不再调用 `Activity.onBackPressed()`**，写在里面的拦截逻辑是死代码。按下返回键时系统直接把任务退到后台，所以表现为「弹窗不关、也不弹确认，直接回桌面」。

修法是挂两条通道：API 33+ 注册 `OnBackInvokedDispatcher` 回调，低版本仍由 `onBackPressed` 兜底，两者都走同一个处理函数，并加了防重入（连按不会叠出两个确认框）。

JS 侧也一并改了处理顺序。原来只派发一个 Escape 事件指望弹窗自己关，但更新弹窗和退出确认框都不监听 Escape，等于没反应。现在按「离用户最近的一层」逐级关闭：

1. 退出确认框开着 → 关它
2. 更新弹窗 → 关它
3. 设置弹窗 → 关它
4. 命令面板 → 关它
5. 播放列表 / 面板 → 收起
6. 其它自绘弹窗 → 派发 Escape 兜底
7. 都没开 → 按设置决定是否二次确认

顺带给更新弹窗补上 `role="dialog"` 与 `aria-modal="true"`（此前只有设置弹窗和退出确认框有，第 6 条兜底认不出它）。

### 0.7.21.14


### 修复

- **长按滑轨滑不动、一滑就消失**：这次找到的是浏览器手势层面的原因。播放页根节点的
  `touch-action` 是默认的 `auto`，手指横向一动，浏览器就判定为滚动手势，直接发出
  `pointercancel` 把整条指针事件流掐断 —— 滑轨刚亮就被收走，后面的 move 也再不会到达。
  现在播放页根节点设为 `touch-action: pan-y`：纵向滚动照旧，横向手势留给应用；同时按下时
